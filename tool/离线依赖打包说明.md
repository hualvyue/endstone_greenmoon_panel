# GreenMoon 面板 · 离线依赖下载打包工具

`fetch_deps.py` —— 把面板与子插件所需的第三方库一次性下载成**离线可用的 wheel 集合**，
供无法联网的服务器使用。

**只用 Python 标准库**，无任何第三方依赖，Python 3.8+ 即可运行。

---

## 一、最常用的一条命令

```bash
python3 fetch_deps.py
```

零参数运行时，它会自动判断：

| 项 | 默认值 | 说明 |
|---|---|---|
| 依赖 | `requests`、`websockets` | 面板 QQ 机器人网关实际需要的两个库 |
| 平台 | 当前平台 | 自动识别 Linux / Windows / macOS 及架构 |
| Python | 当前解释器版本 | 与面板运行环境一致 |
| 输出 | `dist/` | 下载目录 |

跑完得到 `dist/greenmoon-libs-all.zip`，**改名成 `.gmlib`** 后，
在面板「🔌 子插件 → 导入包」上传即可自动入库。

---

## 二、重要：两种产出，用法不同

这是最容易踩坑的地方。面板的 `.gmlib` 导入器是**按包名匹配** wheel 的——
它在归档里扫描，遇到第一个同名 `.whl` 就采用。

### 情况 A：单一平台 + 单一 Python（推荐）

每个包名在归档里天然只有一份 wheel，导入绝对安全。

```bash
python3 fetch_deps.py -p linux-x64 -y 3.11
```

→ 产出可直接改名 `.gmlib` 导入：

```bash
mv dist/greenmoon-libs-all.zip dist/greenmoon-libs.gmlib
```

### 情况 B：跨平台 / 跨版本矩阵

同一个包会有 `cp311` / `cp313` / `win_amd64` 等多个变体，
**直接导入会拿到不确定的变体，很可能是当前平台跑不了的**。

```bash
python3 fetch_deps.py --all-platforms --all-python --split
```

工具会**主动打警告**，并把无法安全导入的包名列出来：

```
⚠ 本次为跨平台 / 跨版本矩阵，一个包名对应多份 wheel。
  ...
  以下 5 个包名存在多平台变体，只能在归档的
  t-<平台>-py<版本>/ 目录里取，请按部署目标手工拷贝：
      charset-normalizer, idna, requests, urllib3, websockets
```

此时**正确用法**是挑一个目标目录，把其中 `.whl` 拷进插件的 `libs/`：

```bash
cp dist/by-target/linux-x64-py3.11/*.whl  <插件数据目录>/libs/
```

然后重启面板。

> **另一种更省心的做法**：对每个部署目标各跑一次本工具（不带 `--all-platforms`），
> 得到的就是可安全导入的单平台包。

## 三、归档内部结构

```
greenmoon-libs-all.zip
├── manifest.json              # 面板读取的清单
├── linux-x64/                 # 可安全进 liblist 的（每个包名全局唯一）
│   ├── requests-2.34.2-py3-none-any.whl
│   └── ...
└── t-linux-x64/               # 同名多份的变体，仅供手工拷贝
    └── websockets-17.1-cp311-...whl
```

`manifest.json` 关键字段：

```json
{
  "name": "greenmoon-libs",
  "python_version": "any",
  "platform": "any",
  "liblist": ["certifi", "idna", "requests", "urllib3"],
  "x-greenmoon": {
    "generator": "fetch_deps.py",
    "safe_to_import": false,
    "needs_manual_copy": ["charset-normalizer", "websockets"],
    "platforms": { "linux-x64": ["..."], "win-x64": ["..."] }
  }
}
```

- `liblist` —— 面板会自动匹配的包名。工具保证这里每个包名在归档中**只有一份 wheel**。
- `x-greenmoon` —— 扩展信息，面板导入时会忽略；`safe_to_import` 告诉你能否直接改名导入。
- 归档内**无重复文件**：同一个 wheel 不会既在 `<平台>/` 又在 `t-<平台>/` 里存两遍。

## 四、参数速查

| 参数 | 说明 |
|---|---|
| `-r, --requirements` | 包名（可多个），或一个 `requirements.txt` 路径 |
| `-p, --platform` | 平台，逗号分隔 |
| `-y, --python` | Python 版本，逗号分隔 |
| `--all-platforms` | 全部 6 个平台 |
| `--all-python` | 全部 6 个 Python 版本（3.8 ~ 3.13） |
| `-o, --out` | 输出目录（默认 `dist`） |
| `--split` | 额外按「平台-py版本」拆分目录，便于直接拷进 `libs/` |
| `--name` | 产出的包名（默认 `greenmoon-libs`） |
| `--no-zip` | 只下载，不打包 |
| `--keep-sdist` | 保留源码包（离线环境通常无法编译，默认丢弃） |
| `--allow-sdist` | 允许回退到源码包（默认强制只取 wheel） |
| `--extra-pip-arg` | 追加 pip 参数，可重复 |

**可用平台**：`linux-x64`、`linux-arm64`、`win-x64`、`win-arm64`、`macos-x64`、`macos-arm64`

**支持的 Python 版本**：`3.8`、`3.9`、`3.10`、`3.11`、`3.12`、`3.13`

## 五、常用示例

```bash
# 只给 Linux + Python 3.11（最推荐的单平台用法）
python3 fetch_deps.py -p linux-x64 -y 3.11

# 带上子插件的额外依赖
python3 fetch_deps.py -r requests websockets "Pillow>=10"

# 用已有依赖清单
python3 fetch_deps.py -r requirements.txt

# 换国内镜像加速
python3 fetch_deps.py --extra-pip-arg=--index-url \
    --extra-pip-arg=https://pypi.tuna.tsinghua.edu.cn/simple

# 全平台 + 全版本，并拆出每个目标的独立目录
python3 fetch_deps.py --all-platforms --all-python --split
```

## 六、失败情况怎么读

某个平台 / Python 组合没有预编译 wheel 时，工具会单独标记，**不影响其他组合**：

```
[1/1] win-arm64-py3.11  —  Windows ARM64
    ✗ 失败: ERROR: Could not find a version that satisfies ...

以下 1 个组合未能完成：
  · win-arm64-py3.11: ERROR: Could not find a version ...

提示：多数情况是该 Python 版本 / 平台组合下，包没有对应的预编译 wheel。
```

这类组合通常是包本身没发布对应平台的二进制包，对面板部署无影响，可以直接忽略。

## 七、注意事项

1. **离线环境不会编译源码包**。工具默认强制 `--only-binary=:all:`，
   确保拿到的都是可直接使用的 wheel。
2. **带 C 扩展的包需要解压才能用**。面板的依赖加载走的是 zip import
   （把 `.whl` 直接挂到 `sys.path`），这种方式只能加载纯 Python 包；
   像 `numpy` 这类含 `.so` / `.pyd` 的包会遇到「无法从 zip 内加载动态库」。
   若子插件确实需要这类包，得改成**解压到 `libs/` 再挂目录**。
   `requests` 与 `websockets` 不受影响——它们的二进制部分在安装后是可选的加速路径。
3. **体积**：全平台全版本约 14.5 MB（以默认两个依赖计），
   依赖越多、平台越全，体积增长很快。生产部署建议只下所需的那一个组合。

## 一、包结构与 manifest

```
你的插件.gmmod
├── manifest.json          必需
└── main/
    ├── main.py            必需（py 型入口）
    └── helper.py          可选，同目录模块可直接 import
```

页面型（`index` / `admin`）不需要 `main/`，但必须有入口 HTML：

```
我的首页.gmmod
├── manifest.json
├── index.html             入口页面（必需）
└── assets/
    ├── style.css
    └── app.js
```

`manifest.json`：

```json
{
  "name": "我的插件",
  "uuid": "my_plugin",
  "version": "1.0.0",
  "min_support_version": "4.2.0",
  "description": "一句话说明",
  "author": "你的名字",
  "type": "py",
  "main": "main/main.py",
  "libs": [],
  "permissions": ["players", "bots", "bindings"]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` / `uuid` / `version` / `min_support_version` / `description` | ✅ | `uuid` 仅允许字母数字、`_`、`-`，**首字符必须是字母或数字**，长度 1–64 |
| `type` | | `index` / `admin` / `py` / `code`；不写等同 `code` |
| `main` | | py 型入口，默认 `main/main.py` |
| `index` | | **页面型**入口，默认 `index.html`；仅 `index` / `admin` 型生效 |
| `libs` | | 依赖的包名列表，需先通过 `.gmlib` 导入 |
| `permissions` | | 申请的面板数据权限，见第十节 |

> `min_support_version` 高于当前面板会**拒绝安装**，报错格式为
> `子插件 X 需要面板 >= 5.2.0，当前 4.2.0`。面板后台的「强制导入」可绕过。

## 二、四种 type 的区别

| type | 落盘目录 | 行为 |
|---|---|---|
| `index` | `mod/index/<uuid>/` | 接管官网首页 `/`，包内文件经 `/gmpage/index/<路径>` 可达 |
| `admin` | `mod/admin/<uuid>/` | 接管管理页 `/admin`，文件经 `/gmpage/admin/<路径>` 可达 |
| `py` | `mod/code/<uuid>/` | 执行 `main/main.py`，可用 `gm` API，支持 `setup`/`teardown` |
| `code` | `mod/<uuid>/` | 旧结构，仅加载模块，不提供 gm 上下文 |

> `index` / `admin` 同一时间**只能启用一个**（后启用者自动顶掉前一个）。
> `py` **允许多个同时启用**，彼此完全隔离。

**安装时的校验强度不同**，这决定了你能踩到哪种错：

| type | 安装时校验 | 失败表现 |
|---|---|---|
| `index` / `admin` | 入口页面**必须存在** | 拒绝安装，报 `必须包含入口页面 index.html` |
| `py` | 入口文件**必须存在** | 拒绝安装，报 `必须包含入口文件 main/main.py` |
| `code` | 入口不存在只记 warning | 装得上，但没东西可加载 |

另外 `index` / `admin` 的启用还会再查一次入口文件，文件被删掉后会拒绝启用并提示
`入口页面 ... 不存在，无法启用`；服务器启动时如果发现入口丢失，会**自动停用**该子插件。

## 三、制作 index 型子插件（接管官网首页）

`index` 型用来替换面板自带的官网首页 `/`。这个页面**无需登录**，任何人都能访问。

### 3.1 最小包

```
skin-gallery.gmmod
├── manifest.json
└── index.html
```

`manifest.json`：

```json
{
  "name": "官网皮肤展示页",
  "uuid": "index_skin_gallery",
  "version": "1.0.0",
  "min_support_version": "5.2.0",
  "description": "把官网首页换成皮肤画廊",
  "author": "示例作者",
  "type": "index",
  "index": "index.html"
}
```

`index.html`：

```html
<!doctype html>
<html lang="zh-CN">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>皮肤画廊</title>
  <link rel="stylesheet" href="/gmpage/index/assets/style.css">
</head>
<body>
  <h1>皮肤画廊</h1>
  <div id="grid"></div>
  <script src="/gmpage/index/assets/app.js"></script>
</body>
</html>
```

### 3.2 入口文件名

入口固定是**包根目录**下的 `index.html`；要用别的名字就写 `index` 字段：

```json
"index": "pages/home.html"
```

`index` 字段可以是子目录路径（如 `pages/home.html`），只要文件真实存在于包内即可。

### 3.3 三条硬性注意点

**① 资源必须用 `/gmpage/index/` 绝对路径引用**

这是最容易踩的坑。`/` 被接管后，页面里的相对引用（`assets/app.js`）会被浏览器解析成
`/assets/app.js`，与子插件目录对不上。

```html
<!-- ❌ 相对引用：会解析成 /assets/style.css，找不到 -->
<link rel="stylesheet" href="assets/style.css">

<!-- ✅ 绝对引用 -->
<link rel="stylesheet" href="/gmpage/index/assets/style.css">
```

面板确实对 `assets` / `static` / `css` / `js` / `img` / `images` / `fonts` / `media` /
`vendor` / `lib` / `dist` 这几个**顶层目录名**做了兜底，但这是兼容性补丁，
不代表可以依赖它 —— 换到 `pages/`、`res/` 之类名字就会 404。**统一用绝对路径**。

**② 这个页面是公开的，拿不到管理接口**

未登录访客请求 `/api/*` 会被鉴权拦下。所以 `index` 页面里**不要**去 `fetch('/api/players')`
之类的管理数据 —— 只会拿到 401/403。

需要展示动态数据时，可选：

- 用 `index` 类型的子插件配合一个 `py` 类型的子插件，由后者把数据**写进包内文件**，
  前者读取（子插件包目录是可写的）；
- 只展示静态内容，把动态部分做成跳转到 `/whitelist` 等公开页面的入口；
- 面板本身已公开的接口只有 `/whitelist`、`/api/whitelist/apply`、`/api/whitelist/status`。

**③ 入口不是 `index.html` / `index.htm` 时会收到一条警告**

```
[子插件] index 子插件 xxx 的入口为 pages/home.html，
        页面内相对资源请改用 /gmpage/index/ 前缀引用
```

只是提醒，不影响使用。

### 3.4 启用与效果

启用后 `active_page('index')` 返回 `(包目录, 入口文件)`，`/` 立即返回你的页面；
停用后 `/` 自动回落到面板自带首页。`/gmpage/index/...` 在启用期间可达，
停用后返回 403/404。

## 四、制作 admin 型子插件（接管管理页）

`admin` 型用来替换面板自带的管理页 `/admin`。与 `index` 的关键区别：

| | `index` | `admin` |
|---|---|---|
| 接管路径 | `/` | `/admin` |
| 前置鉴权 | 无，公开 | **必须先登录**，且要通过 `admin` 的 scope 校验 |
| 静态前缀 | `/gmpage/index/` | `/gmpage/admin/` |
| 可调管理接口 | ❌ 拿不到 | ✅ 浏览器自带会话 Cookie，可直接调 `/api/*` |
| 落盘目录 | `mod/index/<uuid>/` | `mod/admin/<uuid>/` |

### 4.1 最小包

```
mini-console.gmmod
├── manifest.json
├── index.html
└── assets/
    ├── style.css
    └── app.js
```

`manifest.json`：

```json
{
  "name": "精简管理台",
  "uuid": "admin_mini_console",
  "version": "1.0.0",
  "min_support_version": "5.2.0",
  "description": "把 /admin 换成只看在线玩家与广播的精简面板",
  "author": "示例作者",
  "type": "admin",
  "index": "index.html"
}
```

`index.html`：

```html
<!doctype html>
<html lang="zh-CN">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>精简管理台</title>
  <link rel="stylesheet" href="/gmpage/admin/assets/style.css">
</head>
<body>
  <h1>精简管理台</h1>

  <section>
    <h2>在线玩家 <span id="count">–</span></h2>
    <div id="players">加载中…</div>
  </section>

  <section>
    <h2>全服广播</h2>
    <input id="msg" placeholder="输入要广播的内容">
    <button id="send">发送</button>
    <span id="status"></span>
  </section>

  <script src="/gmpage/admin/assets/app.js"></script>
</body>
</html>
```

### 4.2 调用面板接口

`admin` 页面在已登录的浏览器里打开，**请求会自动带上会话 Cookie**，所以直接
`fetch` 面板自己的 `/api/*` 即可，不需要手动传任何凭证：

```js
async function loadPlayers() {
  const res = await fetch('/api/players');
  const data = await res.json();
  const list = (data && (data.players || data.list)) || [];
  document.getElementById('count').textContent = list.length;
}

async function broadcast(text) {
  const res = await fetch('/api/console', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ command: 'say ' + text })
  });
  return await res.json();          // { ok: true, ... } 或 { ok: false, error: "..." }
}
```

**反代子路径部署要特别处理。** 如果面板挂在 `https://host/srv/` 下，
`/admin` 的真实地址是 `/srv/admin`，此时写死 `/api/players` 会打到根上去。
照抄面板自己的做法，从 `location.pathname` 推出前缀：

```js
var API_BASE = (function () {
  var p = location.pathname;                  // '/admin' 或 '/srv/admin'
  return p.slice(0, p.lastIndexOf('/') + 1);  // '/'    或 '/srv/'
})();
function api(u) { return API_BASE + u.replace(/^\//, ''); }

// 之后统一用 api('/api/players')
```

### 4.3 权限范围

`/admin` 本身要求调用者具备 `admin` 的 scope；只要通过了这一关，进入页面后调用的
`/api/*` 仍会**逐条**按登录账户的 scope 校验。

也就是说：**admin 子插件不会提升任何人的权限**。一个只有「查看玩家」scope 的临时账号
即使能打开 `/admin`，他的 `fetch('/api/console')` 一样会被拒。

### 4.4 一个必须知道的行为

接管 `/admin` 后，面板自带的管理界面在启用期间**不再是 `/admin`**。
如果你的子插件只做了一部分功能，管理员就失去了其余功能入口。实际做法有两种：

- 页面里放一个指向原版的链接/按钮，停用子插件即可恢复；
- 直接复制面板前端资源到包内，删改后再接管（包体较大，但完整可控）。

> `/gmpage/admin/...` 在子插件停用后会回落到 `mod/admin/<路径首段>/` 里查找，
> 也就是**未启用也能预览该包自己的资源**（便于开发调试）。

## 五、页面型的资源路径与相对引用

三种引用写法对照（以 `index` 型为例，`admin` 把 `index` 换成 `admin`）：

| 写法 | 解析结果 | 是否可用 |
|---|---|---|
| `/gmpage/index/assets/app.js` | 启用子插件目录下的 `assets/app.js` | ✅ 推荐 |
| `assets/app.js` | 浏览器按当前路径 → `/assets/app.js` | ⚠️ 仅顶层白名单目录有兜底 |
| `./assets/app.js` | 同上 | ⚠️ 同上 |

兜底机制由 `_gmod_asset_served` 实现，只对以下**第一段路径名**生效：

```
assets  static  css  js  img  images  fonts  media  vendor  lib  dist
```

**结论：一律写 `/gmpage/<type>/<路径>` 绝对路径，不依赖兜底。**

### 静态资源能力

子系统发送静态文件时做了这些事，你可以放心用：

| 能力 | 说明 |
|---|---|
| MIME 自动识别 | 按扩展名给 `Content-Type`，`image/svg+xml`、`font/woff2` 等都能正确识别 |
| **Range 支持** | 音视频可拖进度条（返回 206 + `Content-Range`） |
| 流式发送 | 大文件不整体读进内存 |
| 路径安全 | `..`、URL 编码穿越、绝对路径注入全部拦截，越界返回 None |

### 在线编辑包内文件

面板「子插件」页可以**在线查看和编辑**包内文本文件。可编辑的扩展名白名单：

```
.html .htm .js .mjs .css .json .txt .md .svg .xml .csv .yml .yaml .map
```

单文件读取上限 512 KB。这让你可以在服务器上直接改页面、改完刷新即可（页面型改动立即生效，
不需要重启），是调试 `index` / `admin` 页面的最快方式。

## 六、制作 py 型子插件

`py` 型会**真正执行代码**，能力最全，`index` / `admin` 做不到的事情靠它完成。

`main/main.py`：

```python
from gm import server, players, bot

def setup(plugin=None, gm=None):
    """启用时调用。两种签名都兼容：setup(plugin) 也行。"""
    server.broadcast("§a我的插件已上线")
    print("在线玩家：", players.names())

def teardown(plugin=None):
    """停用时调用。在这里收干净自己的线程/连接/定时器。"""
    print("我的插件已下线")
```

启用后，插件会以 `greenmoon_mods.<uuid>` 的模块名加载，**在这两个钩子之外写的模块级代码也会立即执行**，
所以别忘了 `setup` 只写该在启用时跑一次的东西。

## 七、快速开始

1. 准备好包目录与 `manifest.json`。
2. 打包：**进到目录里**再压缩，确保 `manifest.json` 在 ZIP 的**根**。
   ```bash
   cd 我的插件 && zip -r ../我的插件.gmmod . -x ".*"
   ```
3. 面板 →「子插件」→ 上传 `.gmmod`。
4. 在列表里点「启用」。

> 打包时不要多套一层目录（`我的插件/manifest.json` 在 ZIP 里是对的，
> `xxx/我的插件/manifest.json` 就会报「未找到 manifest.json」）。

## 八、API 参考

### 1. 机器人 API（`gm.bot`）

多机器人按「卡片」维度，用 `adapter_id` 指定具体哪一台。

```python
from gm import bot

bot.list()                    # 全部机器人卡片
bot.primary_id()              # 主机器人 id
bot.info(bot_id)              # 自身信息：名称/类型/是否启用/是否连接/app_id/群数
bot.groups(bot_id)            # 群聊列表 [{openid, name, is_primary}]
bot.group(bot_id, openid)     # 单个群聊详情（含是否已绑定玩家）
bot.status(bot_id)            # 运行状态
bot.is_connected(bot_id)      # 是否已连接
bot.send_group(bot_id, group_id, "内容")        # 发群消息
bot.send_group_async(...)     # 不等待，丢后台线程
```

### 2. Endstone 原生 API

`server` / `player` 返回的是**未经包装的原生对象**，`isinstance` 断言依然成立：

```python
from gm import server, player

srv = server.get()                     # endstone Server 原生对象
server.broadcast("消息")                # 已切主线程
server.dispatch("say hi")              # 执行控制台指令
server.online_players() / player_count()

p = player.find("Steve")               # 原生 Player 对象
player.tell("Steve", "你好")
player.kick("Steve", "违规")
player.teleport("Steve", 0, 64, 0)
player.health("Steve", 20)

# 需要动服务器状态时，切回主线程执行
def _buff(pl):
    pl.health = 20
player.run_on("Steve", _buff)
server.run(lambda: server.broadcast("在主线程广播"))
```

> **线程安全**：Endstone 的服务器对象只能在主线程碰。`gm` 里带「包装」的接口
> （`teleport`/`kick`/`tell`/`run_on`/`server.run`/`dispatch`）会自动切到主线程并等结果；
> 纯读接口（`players.*`、`admin.*`）读的是面板缓存，任何线程都能直接调，不阻塞。

### 3. 面板数据 API

```python
from gm import admin, console

admin.system_stats()     # CPU / 内存 / 磁盘 / 运行时长
admin.players_snapshot() # 面板缓存的玩家列表
admin.online_names() / admin.online_count()
admin.messages(limit=50) # 局内聊天记录
admin.state()            # 综合快照（未授权板块返回 "__denied__"，不抛异常）

console.logs(limit=200)  # 控制台日志
console.tail(20)
console.run("say hi")    # 执行控制台指令
```

### 4. 玩家 QQ 绑定数据（`gm.bindings`）

```python
from gm import bindings

bindings.all()             # {"by_qq": {...}, "by_mc": {...}}
bindings.by_qq(openid)     # -> 玩家名
bindings.by_mc("Steve")    # -> {qq, mc, bound_at}
bindings.exists("Steve")
bindings.count() / pairs()
```

### 5. 跨服玩家数据（`gm.cross`）

```python
from gm import cross

cross.enabled() / role() / is_master() / is_slave()
cross.server_name() / status() / config()

cross.get_player(uuid)              # ⚠️ slave 模式下是同步 HTTP，会阻塞
cross.get_player_async(uuid, cb)    # 推荐：不阻塞
cross.put_player(uuid, name, data)  # 写入本服数据
```

### 6. 游戏事件（`gm.event`）

```python
from gm import event
from endstone.event import PlayerChatEvent, PlayerJoinEvent

@event.on(PlayerChatEvent)          # 装饰器写法
def on_chat(ev):
    if "帮助" in ev.message:
        ev.player.send_message("§e试试 /spawn")

event.on(PlayerJoinEvent, on_join)  # 普通调用写法也行

event.off(PlayerChatEvent, on_chat) # 取消注册
```

**已支持的事件类型**：

```
PlayerChatEvent
BroadcastMessageEvent
PlayerJoinEvent
PlayerQuitEvent
```

可用 `event.supported()` 在运行时查询这张表。其它类型可以用 Endstone 原生方式自己注册。

> 子插件停用时，它注册的所有 handler 会**自动摘除**，不会残留。

## 九、调用者身份与线程

`from gm import current_owner` 会告诉你「当前是哪个子插件在调用」：

```python
from gm import current_owner
print(current_owner())   # 'my_plugin'
```

面板靠模块名 `greenmoon_mods.<uuid>` 沿调用栈反查身份，因此：

- ✅ 子插件**自建线程**里依然能正确识别（定时器、网络回调都没问题）
- ✅ 多个 py 子插件**同时运行**互不串扰
- ✅ 同目录的 `helper.py` 里调用，识别的仍是所属子插件的 uuid

## 十、权限

涉及面板数据的模块（`bot` / `bindings` / `cross` / `admin` / `console`）需要在 `manifest.json`
的 `permissions` 里声明：

```json
"permissions": ["players", "logs", "console", "bots", "bindings", "cross"]
```

| 权限 | 覆盖的接口 |
|---|---|
| `players` | `admin.system_stats` / `cache` / `players_snapshot` / `online_*`，`players.*` |
| `logs` | `admin.messages` |
| `console` | `console.*` |
| `bots` | `bot.*` |
| `bindings` | `bindings.*` |
| `cross` | `cross.*` |

写 `"*"` 表示全部。**未声明就调用**会抛 `GmPermissionError`：

```python
from gm import GmPermissionError, admin
try:
    admin.system_stats()
except GmPermissionError as e:
    print("没权限：", e)
```

游戏侧能力（`server` / `player` / `event`）**不需要**任何权限。

### 完整权限清单

`permissions` 里写别的名字会在**安装时直接报错**（避免拼错后静默失效）：

```
players  logs      console  detail   bots     bindings  cross    mods
backup   cloud     gamerules worlds  perm     scoreboard gametools files
diag     account
```

### 权限是「声明式」而非「沙箱」

`permissions` 只约束 `gm.*` 那套封装接口。`py` 型子插件执行的是**任意 Python 代码**，
理论上可以绕过 `gm` 直接读面板数据目录。

因此面板把**子插件管理限制为仅 admin 角色可操作**（临时账号一律拒绝，见
`_gmod_admin_only`）。**只安装你信任的子插件** —— 这与「装一个插件」是同等信任级别。

## 十一、生命周期

| 时机 | 钩子 | 说明 |
|---|---|---|
| 启用 | `setup(plugin=None, gm=None)` | 可选。模块加载后调用 |
| 停用 | `teardown(plugin=None)` | 可选。模块移出内存前调用 |
| 服务器启动 | — | 已启用的 py 子插件会**自动重新加载**并再次调用 `setup` |
| 服务器关闭 | `teardown` | 会先全部 teardown 再清模块 |

再次点「启用」等于**热重载**：先卸干净（跑 `teardown`）再重新加载，改动立即生效。

> ⚠️ 在 `teardown` 里务必停掉自己起的线程 / 关闭连接，否则热重载会留下孤儿线程。

**页面型（`index` / `admin`）没有钩子**，因为不执行代码。启用状态记在
`mod/gmod.json`，重启服务器后自动恢复。

## 十二、调试与常见坑

**看日志**：面板「子插件」页可在线查看/编辑包内文件；运行日志走服务端控制台，前缀 `[子插件]`。

### 安装阶段

| 现象 | 原因 |
|---|---|
| `未找到 manifest.json` | ZIP 里多套了一层目录；`manifest.json` 必须在根 |
| `uuid 非法` | uuid 含中文、空格，或以 `_`/`-` 开头 |
| `type 非法` | `type` 值不是 `index`/`admin`/`py`/`code` |
| `必须包含入口页面 index.html` | 页面型的入口 HTML 没打进包，或路径与 `index` 字段不符 |
| `必须包含入口文件 main/main.py` | py 型入口没打进包，或路径与 `main` 字段不符 |
| `permissions 含未知权限: xxx` | 权限名拼错，对照第十节的完整清单 |
| `需要面板 >= x.y.z，当前 a.b.c` | `min_support_version` 写高了 |

### 运行阶段

| 现象 | 原因 |
|---|---|
| `ModuleNotFoundError: No module named 'gm'` | 面板版本低于 4.2.0，或 `type` 不是 `py` |
| `ModuleNotFoundError: No module named 'helper'` | 同目录模块应放 `main/` 下；入口必须在 `main/main.py` |
| `GmPermissionError` | `permissions` 没声明对应权限 |
| `GmNotReady` | 面板还没加载完就调用了 gm |
| 服务器卡顿/崩溃 | 在非主线程直接改原生对象，改用 `player.run_on` / `server.run` |
| `setup()` 不执行 | 函数名写错，或定义在类里（必须是模块级函数） |
| **页面样式/脚本 404** | 用了相对引用；改成 `/gmpage/<type>/...` 绝对路径 |
| **`/admin` 打开是空白或 404** | 入口文件名不是 `index.html`/`index.htm`，看控制台的 `[子插件]` 警告 |
| **`/admin` 里 fetch 接口失败** | 反代子路径部署下写死了 `/api/...`，改用 `API_BASE` 拼前缀 |
| **`index` 页面取不到数据** | `/` 是公开页，未登录拿不到 `/api/*`，见 3.3 ② |

### 本地自测

入口模块的加载逻辑等价于：

```python
import importlib.util, sys
spec = importlib.util.spec_from_file_location("greenmoon_mods.my_plugin", "main/main.py")
mod = importlib.util.module_from_spec(spec)
sys.modules["greenmoon_mods.my_plugin"] = mod
spec.loader.exec_module(mod)
```

## 十三、打包与发布清单

发布前逐项过一遍：

- [ ] `manifest.json` 在 ZIP **根目录**
- [ ] `uuid` 只含字母数字、`_`、`-`，首字符是字母/数字
- [ ] `version` / `min_support_version` 是 `x.y.z` 形式
- [ ] `type` 正确（`index` / `admin` / `py` / `code`）
- [ ] 页面型：入口 HTML 存在，且与 `index` 字段一致
- [ ] 页面型：所有资源引用都是 `/gmpage/<type>/...` 绝对路径
- [ ] py 型：入口在 `main/main.py` 或 `main` 字段指定处
- [ ] py 型：`permissions` 只写需要的，且名字在合法清单里
- [ ] py 型：`teardown` 里清理了自己的线程 / 连接 / 定时器
- [ ] 打包命令用的是 `cd 目录 && zip -r ../x.gmmod . -x ".*"`

打包：

```bash
cd 我的插件 && zip -r ../我的插件.gmmod . -x ".*"
```
